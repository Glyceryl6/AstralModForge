# 星航 MOD 工坊 v0.3.0 · 使用手册 / User guide

## 1. 环境与安装

插件目标为 Rider 2025.2.x，JDK 21，Gradle 9.0.0+，IntelliJ Platform Gradle Plugin 2.20.0。独立 MOD 的构建还需要能编译 `net6.0` 的 .NET SDK、NuGet 依赖与适配的 BepInEx IL2CPP 游戏环境。

源码工程执行：

```bash
gradle coreChecks
gradle buildPlugin
```

将 `build/distributions/*.zip` 安装到 Rider：**Settings → Plugins → Install Plugin from Disk**，安装后重启。随附 `preview-install.zip` 只是离线候选包，不应取代真实 SDK 下的 `buildPlugin` 结果。运行 `gradle runIde` 可使用沙盒 IDE 检查菜单、文件树、工具窗口与日志显示。

## 2. 新建空 MOD / Create a project

在 Rider **Tools → Astral Mod Forge / 星航 MOD 工坊 → Create New MOD / 新建独立 MOD**，输入 MOD ID，例如 `dev.example.hello`。

生成 `Plugin.cs`、`.csproj`、`ModLocalization.cs`、`Features/SampleFeature.cs` 与 `lang/zh_cn.json`、`en_us.json`。默认目录为 `<工作区>/AstralModForge/Projects/<ID>/`；如果打开的是含 `.csproj` 的源工程根目录，为防止 C# 默认 glob 编译重复类，输出改为 `<工作区同级>/AstralModForge-Projects/Projects/<ID>/`。

生成项目带 `net6.0` 目标框架。编译前核对游戏要求的 BepInEx 和 SNWCreations 依赖版本、`Plugin.Load()` 里初始化的示例功能。内嵌 JSON 是 C# 项目的 `<EmbeddedResource>`，与 Java 插件本身的 JAR 是两种独立资源机制。

## 3. 从已有 MOD 导出功能 / Export selected classes

1. 打开原工程；确保 C# 编辑器中的修改**已经保存到磁盘**。从项目视图预选 `.cs` 文件也可以，不必按住 Shift。
2. **Tools → Astral Mod Forge → Export Selected Classes / 导出选中类**。
3. 输入新的 MOD ID，在树形目录中展开文件夹、勾选需独立启动的功能类。勾选会选上可静态识别的下游依赖与 `partial` 文件；取消某个依赖文件时，依赖它的上游功能也会取消。目录复选框支持批量勾选与部分勾选状态。
4. 如有必要填写入口，格式 `Namespace.Type::Initialize;Namespace.Type::Install`，每帧用 `Namespace.Type::Tick`。**依赖工具类不会因为有同名方法而自动启动**。一旦不能安全识别任何启动入口，预检会阻止导出。
5. 使用 **Check dependencies / 检查依赖** 检查闭包和不支持的调用。尤其检查本地化动态键、原配置依赖、跨模块 SDK 与原 HotfixWatcher 中的生命周期。
6. 选择本地化：**Embedded JSON / 内嵌 JSON**（推荐，独立 MOD 语言资源）或者 **Inline fixed text / 编译时转换为固定文本**（只替换明确的字面量键名，缺失、动态键不强制猜测）。
7. **Build DLL / 编译 DLL** 默认开启；**Export C# source / 同时导出 C# 源码** 默认关闭。若关闭编译，会自动要求导出源码，避免无交付产物。
8. 可选 **Embed default settings in DLL / 将默认设置内嵌到 DLL**：开启后，将能够解析为 C# 字面量的 `ConfigEntry<int/float/double/string>` 默认值直接放入导出功能源码，并从生成的 `Plugin.cs` 去掉配置保存操作。内嵌语言 JSON 仅从 DLL 读取，固定使用下拉选择的 `zh_cn` / `en_us`；不再生成此 MOD 的默认 `.cfg`、语言 JSON 文件。不会删除旧 `.cfg` 或其它历史文件；自定义文件读写仍可能需要人工改造。
9. 可选 **Copy DLL to game / 编译成功后复制 DLL 到游戏目录**，选择游戏**根目录**，不是 `BepInEx/plugins` 子目录。目录校验不通过时跳过部署，保留编译产物。
10. 导出后查看底部 **Astral Mod Forge** 工具窗口中的进度／日志，以及生成目录的 `export-report.md`、`build.log`。

## 4. 勾选源码的输出位置与防重复类

默认源码不导出，在 OS 临时目录构建：

```text
<原工程>/AstralModForge/Exports/dev_example_mod-时间/
  export-report.md
  export-manifest.properties
  build.log                    # 调用了 dotnet 时
  dist/dev_example_mod.dll    # 仅编译成功时
```

原工程中的任何源码都不会被修改，临时工程最终被删除。**不勾选源码且没有 dotnet 或编译失败，只有日志和报告，不会伪造 DLL。**

勾选源码时，默认输出到原项目同级的 `<原工程>-ForgeExports/Exports/...`，保留 `.csproj`、`Plugin.cs`、`Source/`、`lang/` 等完整工程。自定义路径不得在原 C# 工程内部；工具会拒绝这一危险路径。

若你直接从 `examples/` 生成新 MOD，同样建议作为单独的 Rider/.NET 项目打开，避免原始 `.csproj` 的默认 `**/*.cs` 扫描将它编译进去。

## 5. 设置自动剥离（开启状态）

对于原 MOD 中能够**明确确认是 `ConfigEntry<bool>`** 的开关，只转换读取位置，例如：

```csharp
// 原 MOD：
if (!Plugin.AutoPraisePlayers.Value) return;
// 导出：
if (!true) return;
```

不把原宿主的 `Framework.Settings`、配置模块或设置页注册机制一起打包，也不新增这些开关的独立设置选项。勾选内嵌默认配置后，可把明确的非布尔默认值（整数、浮点数、字符串）编入源代码；无法解析的默认表达式、设置对象直接传递、`Value` 写入或 `ref/out` 仍会报错。**这里不等同于把原 MOD 里所有功能、所有设置或游戏自身配置都强制启用。**

如果业务类不仅检查一个开关，还依赖原设置页实例、图标或另一个 MOD 的初始化顺序，必须重构调用链，不应盲目复制源文件。生成的独立 `Plugin.cs` 提供自己的 `Load()`，必要时挂接 `Tick()`，而不复制旧 `HotfixWatcher`。

## 6. 语言与构建日志

本工具的 UI 语言采用 JetBrains `DynamicBundle` 绑定 `Messages.properties`（英文）与 `Messages_zh_CN.properties`（简体中文）；菜单、窗体、按钮、工具窗口标题各自按 IDE 语言加载，而不是拼接两种语言到一个按钮里。构建过程中的后端异常与部分底层诊断仍可能是双语文本，它们不属于按钮名称。

导出的 MOD 本地化使用自身 GUID 的 JSON 和 `EmbeddedResource`；固定文本模式只对可静态识别的翻译调用做安全替换。勾选内嵌默认配置后，默认语言文件只作为 DLL 的嵌入资源，不会在运行时创建外部语言文件、配置项或者热更新轮询。`CurrentLocale` 映射到独立语言服务。

工具窗口可以清空／复制日志，编译器输出同时写入导出目录的 `build.log`。后台任务允许取消；游戏目录部署仅在 `dotnet build` 返回成功且找到了预期 DLL 后执行。输出日志请注意可能含开发机本地项目路径，公开问题报告时可先编辑脱敏。

## 7. CLI

```bash
# 新建工程
java -jar AstralModForge-v0.3.0-standalone-cli.jar new \
  --id=dev.example.hello --project=/path/to/workspace

# 默认只尝试编译 DLL，不留 C# 源码
java -jar AstralModForge-v0.3.0-standalone-cli.jar export \
  --id=dev.example.autopraise --project=/path/to/AstralProbe \
  --classes=Features/Automation/AutoPraiseService.cs

# 只导出可编辑 C# 工程，不执行编译
java -jar AstralModForge-v0.3.0-standalone-cli.jar export \
  --id=dev.example.autopraise --project=/path/to/AstralProbe \
  --classes=Features/Automation/AutoPraiseService.cs --export-source --no-build
```

内嵌默认配置可附加 `--embed-default-config`，不会改变 CLI 的源码导出默认值。

其他参数：`--lang=embedded|inline`、`--locale=zh_cn|en_us`、`--load=Namespace.Type::Initialize`、`--update=Namespace.Type::Tick`、`--output=/safe/output/dir`、`--copy --game=/game/root`。

## 8. 测试及风险

离线 Java 21 核心测试 **69 项通过**。还验证了 AstralProbe v0.47.0 的 `AutoPraiseService` 导出源码：不包含原设置类，布尔开关默认启用，保留独立入口。**这不等于 `.NET` 编译或游戏内验证**；没有真实 JetBrains Rider SDK，也无法从离线候选 ZIP 推断所有安装和 API 兼容情况。

部分问题不可纯靠 Java 前端解决：反射、Harmony 注册、间接委托、缺失的 ReSharper 调用关系、Unity 生命周期、IL2CPP 类型注册和原项目外部依赖。遇到这些情况请依据错误报告、编译日志补充明确的手工入口或代码改造。
