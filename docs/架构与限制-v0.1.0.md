# Astral Mod Forge v0.1.0 · 架构与边界 / Architecture & boundaries

## Rider 前端与 C# 后端 / Rider frontend vs C# backend

Rider 前端是 JVM（IntelliJ Platform），C# 的完整 PSI/语义分析主要在 ReSharper 后端。根据 JetBrains 的架构文档，**纯 Java 前端无法直接拿到完整 C# 语义调用图**。本版采用无 IntelliJ 依赖的 Java 导出核心，使用保守的源码索引并以真正的 `.NET` 编译诊断兜底。不能承诺对反射、跨程序集扩展方法、泛型推断、Harmony 自动注册、Unity 内部回调完成语义级重写。

未来有明确需求时可增加一个可选 .NET ReSharper/Roslyn 伴生后端，为每个类型输出真实依赖边、可访问构造器、事件订阅与生命周期元数据；Java 插件仍只负责 UI 和过程编排。

## 模块

| Java 类 | 用途 |
|---|---|
| `CSharpIndex` | 屏蔽注释和字符串，读取部分 `.csproj` 排除规则，构建类型和文件索引；不索引旧 `Modules`、addon、测试和生成目录 |
| `DependencyPlanner` | 解析可见同工程类型依赖，补齐 `partial`，检查宿主 API、识别 `Init/Install/Initialize/Tick` 与显式多个入口；不自动启动依赖工具类 |
| `LocalizationTransformer` | 严格检查与替换字面量翻译键；动态键在固定模式被拒绝，资源可按独立 MOD ID 组织 |
| `ModTemplates` | 生成 `net6.0` `.csproj`、`Plugin.Load()`、`ForgeTickBehaviour`、独立 `.NET` 本地化实现与兼容桥 |
| `ForgeExporter` | 创建工作目录、生成报告、`dotnet build`、仅成功后生成 dist/复制 DLL |
| `GameInstaller` | 校验实际游戏/BepInEx 文件夹、软链接路径、备份旧 DLL 后复制 |
| `cli.Main` | 无 Rider 依赖的可复现命令行入口 |
| `ide.*` | Java Swing + IntelliJ `AnAction` 菜单与后台进度；不承担 C# 静态分析本体 |

## 调用链与加载约束

- 原始宿主的 `Plugin.cs` 和 `HotfixWatcher.cs` 不参与复制。每个导出独立生成 `Plugin`，避免误编译整套 AstralProbe 宿主。
- 每个选择的类如果只有 `Tick(float)`，就会生成一个独立的持久实例，并从 `ForgeTickBehaviour.Update` 的主线程调用。
- 同时选择多个带有 `Init`、`Install`、`Initialize` 的类时会生成多个 `Plugin.Load` 调用；不确定的重载要求用户明确指定。
- 生成的 `ConfigEntry<bool|int|float|string>` 使用单独的 `[ExportedFeature]` 分组，**默认值需人工核对**，不复制原用户 cfg 及宿主设置页面。
- 任何未知的 `Plugin.X` 引用都会在预检阶段失败；即使编译成功，事件订阅、Hook 去重、卸载清理也需开发者在游戏内检查。
- `dotnet build` 是语法和外部依赖的第二道检查，**不能证明功能已加载/运行**。当前环境没有可用的 .NET SDK，没有进行此步验证。

## 不修改原源码 / No source mutation

生成工程总是位于全新日期目录下，不复制回源项目，不改原类命名空间，也不打包原 `Plugin`。这样不会在 AstralProbe 本身产生新旧同名类的编译冲突。

## 资源隔离

- 翻译字典：以 MOD GUID 为前缀的内嵌 `lang/*.json`；运行时覆写路径 `BepInEx/config/<MOD ID>/lang`。
- 配置：BepInEx 生成 GUID 对应的独立 cfg；从原宿主代理的简单配置放到 `ExportedFeature` 分组。
- 本地化键不可能总是安全重命名：设置页传参可能有业务 ID 含义；因此裸键被标记为风险，而不是粗暴替换所有相同字符串。
- 若多 MOD 同时引用 `AstralParty.Modding.SDK.dll`，请约定公共 SDK 的包版本和放置位置，避免程序集版本冲突。

## 已知限制 / Known limitations

1. **C# 源码扫描并非完整编译器**：只支持常见的单命名空间类声明与简单同名引用；复杂 `global using`、同名类型、泛型与反射需要审查。
2. **本地化键自动替换只支持简单调用**：原版 SDK UI 的标签键、动态字符串拼接、包含格式化逻辑的表达式需要重构或人工确认。
3. **生命周期自动化有限**：只接线已知 `Load` 和 `Update` 方法；Harmony 属性注册、IL2CPP Type 注册、协程、回调解绑尚需显式模块实现。
4. **外部构建依赖**：如果生成工程保留绝对 `ProjectReference`，跨机器前需要修复路径；NuGet 还原也需要相应网络与缓存。
5. **游戏目录安全保护**：只复制生成的 DLL 和显式项目 SDK 构建产物，拒绝未识别游戏目录或符号链接越界；遇到失败不做破坏性清理。
6. **尚未完成实际 Rider SDK 验证**：预编译 ZIP 是安装候选；须在有网络的 Rider/IntelliJ 中用真实 Gradle `buildPlugin` 重建，再启动 Rider 验证两个菜单动作。
